## 2. 用例设计方法对照

| 方法 | 在本项目中的例子 |
|---|---|
| 等价类 | 合法/非法币种、合法/非法数量区间 |
| 边界值 | `quantity` 1 / 100 / 0 / 101；`limit` 1 / 100 / 0 / 101 |
| 判定表 | "订单状态 × 操作" 组合：已支付能否取消/删除，待支付能否支付 |
| 场景法 | 创建 → 查询 → 支付 → 取消（应 409）；创建 → 删除 → 查询（应 404） |
| 错误推测 | 重复提交、金额传字符串、Unicode 客户 ID、超长 SKU、额外字段批量赋值 |
| 正交/组合 | 属性测试用 Hypothesis 自动生成明细组合，验证金额不变量 |
| 契约比对 | 响应字段与 JSON Schema 逐字段比对，多字段/少字段都算破坏性变更 |

## 3. 接口测试执行流程（可直接搬到工作里）

```text
需求/接口文档
   ↓ 提取接口清单 + 业务规则 + 状态机
接口清单与优先级（P0 核心链路 / P1 主流程 / P2 边缘）
   ↓
用例设计（本矩阵逐格填）
   ↓ 用例评审（开发 + 产品 + 测试）
执行：Postman/Apifox 调试 → Pytest 自动化回归 → 契约测试进 CI
   ↓
缺陷提单 → 修复验证 → 回归 → 关闭
   ↓
测试报告（通过率、覆盖率、遗留风险、上线建议）
```

### 3.1 工具分工

| 工具 | 用来做什么 | 不适合做什么 |
|---|---|---|
| Postman / Apifox | 单接口调试、造数据、临时验证、给别人复现 | 长期回归（集合会腐化、断言弱） |
| Pytest + Requests | 主回归、数据驱动、依赖编排、CI | 探索性测试 |
| JSON Schema / OpenAPI | 契约守门，拦截破坏性变更 | 替代业务逻辑断言 |
| Locust / 自研 runner | 性能基线、拐点、故障注入 | 功能验证 |

### 3.2 Postman/Apifox 集合该怎么组织（灵狐入职可直接用）

```text
Collection: 业务系统接口
├── 00 环境变量（base_url / token / 测试账号）
├── 01 鉴权
│   └── 获取 Token（Tests 里 pm.environment.set("token", ...)）
├── 02 核心链路（按业务排序，可一键 Run）
│   ├── 创建订单 → 保存 order_id
│   ├── 查询详情（断言字段、金额）
│   ├── 支付（断言状态流转）
│   └── 取消（断言 409）
├── 03 异常用例（参数缺失、越权、重复提交）
└── 04 数据校验（查询后用 SQL 对账）
```

关键点：**Token 自动写入环境变量、ID 自动传递、每条请求都有状态码 + 关键字段断言**。没有断言的集合只是"能点通"，不算接口测试。

## 4. 缺陷分级与提单模板

| 级别 | 定义 | 例子 | 时限 |
|---|---|---|---|
| P0 | 核心链路不可用、资金/数据错误、鉴权绕过 | 未登录可下单、金额算错、重复扣款 | 立即，阻断发布 |
| P1 | 主要功能错误、契约破坏性变更 | 支付超时未置 FAILED、响应少字段 | 当版本修复 |
| P2 | 次要功能/提示/分页错误 | 列表第二页重复数据 | 近期迭代 |
| P3 | 体验/边界/文档问题 | 错误提示不友好 | 记录观察 |

提单模板：

```text
标题：[模块] 一句话现象（环境/条件 + 结果）
环境：测试环境 / 版本号 / 账号
前置条件：
复现步骤：1. 2. 3.（每步可执行，不含"大概""可能"）
预期结果：
实际结果：
复现率：必现 / 3/5
附件：请求响应、日志、截图、SQL 结果
初步定位：前端 / 接口 / 数据 / 环境（附证据）
影响范围：哪些用户/功能受影响
```

## 5. 接口测试的准出标准

1. P0/P1 用例 100% 通过；
2. 契约测试通过，OpenAPI 合法；
3. 无未关闭的 P0/P1 缺陷；
4. 新增/变更接口有对应用例与契约；
5. 回归集通过率 100%，失败项已定性（缺陷/环境/用例问题）；
6. 报告归档：范围、通过率、覆盖率、遗留风险、上线建议。

## 6. 面试被问"你怎么设计接口用例"时的 30 秒答法

> 我先按"鉴权、参数、业务规则、异常与幂等、数据一致性、契约、安全、性能"八个维度列矩阵，再把矩阵逐格落到具体接口上——有些格子对该接口无意义就明确写原因。
> 参数层用等价类和边界值，业务层用状态机和判定表，异常层靠故障注入和错误推测，最后用契约测试守住字段变更、用数据库断言确认真的落库。
> 这套矩阵在这个项目里落成了 87 条用例，六层目录，CI 全绿。
